chore: member output probe (session/event) + verify the stale-lock handler exists

Two things this round:

1. Stale ledger locks are already handled in-tree: LedgerWriter._acquireLock
   reads the lock, and _isStaleLock treats an unreadable/invalid/pid-less
   record as stale (takeover) and, on the same host, a dead pid as stale.
   It only refuses to take over when the record names a different host -
   which is the conservative behaviour for shared directories. So no new
   code is needed for the requested "automatic stale lock cleanup"; the
   restart failures seen earlier came from those records (manual removal
   unblocked boot and the next boots took over automatically).

2. The SDK routes to close item 4 are exhausted: dsh-agent ships no .d.ts
   (only .js + README), its README/types do not describe the agent/created
   argument shape, and cordis-inspect is not installed, so
   cordis_inspect_query is unavailable. The remaining observable path is
   the session/event probe added here: it records every assistant message
   produced by a member session so we can see whether the member works at
   all. It produced no rows for the reviewer, which itself is informative -
   either the member produced no assistant message or runtimeForAgent does
   not yet resolve its rebuilt session.
